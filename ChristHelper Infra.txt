CHRISTHELPER – TECHNICAL OVERVIEW (v1 – LOCAL DEV)

---

1. PROJECT OVERVIEW

---

ChristHelper is a web platform designed to connect Christians who need help (financial, prayer, guidance) with supporters.

Core features:

* Submit projects (requests for help)
* Browse and explore projects
* Donate to projects via Stripe
* Track prayers and replies
* Stripe Connect for project owners
* Admin review for financial approval

---

2. ARCHITECTURE (CURRENT)

---

Type: Monolithic (Frontend + Backend separated but simple)

Frontend:

* Static HTML/CSS/JS
* Served via local dev server (e.g. http://localhost:59922)

Backend:

* Node.js (Express)
* Runs on http://localhost:3000

Data storage:

* JSON file (data.json)
* No database yet (planned upgrade later)

Payments:

* Stripe Checkout
* Stripe Connect (Express accounts)

---

3. TECHNOLOGIES USED

---

Backend:

* Node.js (v24+)
* Express.js
* Stripe SDK
* JWT (authentication)
* bcrypt (password hashing)

Frontend:

Payments:

5. LOCAL DEVELOPMENT – HOW TO RUN

---

IMPORTANT: You need 3 terminals running

---

## (1) BACKEND

Go to backend folder:

cd C:\dev\christhelper\backend

Run:
node server.js

You should see:
ChristHelper backend running on http://localhost:3000

---

## (2) FRONTEND

Go to frontend folder:

cd C:\dev\christhelper\frontend

Run a local server (example using "serve"):

npx serve .

OR if you use another tool:

* Live Server (VS Code)
* http-server

Example result:
http://localhost:59922

Open browser:
http://localhost:59922/index.html

---

## (3) STRIPE WEBHOOK (VERY IMPORTANT)

Open a NEW terminal and run:

stripe listen --forward-to localhost:3000/webhook

You should see:
Ready! Your webhook signing secret is whsec_...

Copy that secret into .env:

STRIPE_WEBHOOK_SECRET=whsec_...

IMPORTANT:

* Keep this terminal OPEN while testing payments
* Without this, payments will NOT update your project

6. PAYMENT FLOW (IMPORTANT)

---

1. User clicks "Support Project"

2. Frontend calls backend:
   POST /payments/project-checkout

3. Backend:

   * Creates donation record (status: pending)
   * Creates Stripe Checkout session
   * Returns session URL

4. User completes payment on Stripe

5. Stripe sends webhook:
   event: checkout.session.completed

6. Backend webhook:

   * Finds donation via metadata
   * Marks as paid
   * Updates project.amount_raised

7. Frontend refresh → updated value
